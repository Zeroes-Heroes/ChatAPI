# Message sync wire contract v1

Stage 01 only. These additive DTOs do not change the legacy hub, database, authentication or UI. Server types live in Services/Sync/Contracts; client types in src/Types/Sync. Integration belongs to later plans.

## Encoding and identity

Use JSON, camelCase properties, exact case-sensitive string enums, explicit nulls and UTF-8. The future v1 transport must opt into SyncProtocol.CreateJsonOptions(); never use the legacy MessagePack resolver. Proposed route prefixes are /sync/v1 for HTTP and a separately versioned hub. Unknown protocolVersion fails before mutation. Additive outer fields are ignored within deployed v1; removed fields, changed semantics, new enum values or signed payload formats require a new negotiated version. These currently unpublished stage-01 contracts may be extended before v1 is activated. Exact enum names are enforced by the shared strict converter; lowercase, whitespace, numeric and combined names are rejected. DTO deserialization is not input validation: handlers must validate required values and cross-field invariants.

IDs are case-sensitive ASCII tokens matching [A-Za-z0-9_-]{1,128}. Existing numeric entity IDs become decimal strings; new account contexts, registrations, instances, memberships, operations and snapshots use lowercase UUIDs. Sequences, versions and counts are canonical decimal nonnegative Int64 strings, max 9223372036854775807; never JS numbers. UTC timestamps use RFC3339 with exactly three fractional digits and Z. Binary wire data uses canonical unpadded base64url. Probe fixture base64 is explicitly not wire encoding.

AccountContextId denotes ownership/authorship and changes for a fresh start on the same phone. DeviceRegistrationId denotes a registration with a verified possession key, not a hardware ID. LocalInstanceId denotes one SQLite copy; clearing it requires full sync. MembershipId denotes an access period; RightsVersion changes with access. OperationIdentity is the entire tuple of account, registration, instance and ClientOperationId and is persisted before transmission. SessionId/TrustVersion bind device authorization; ConnectionId/SyncSessionId are temporary and never replace operation identity.

## Immutable message package

SendText is the sole v1 operation. Trim text and reject empty input. Plaintext is raw UTF-8 text, max 8192 bytes. Each new message uses a random 32-byte AES key, random 12-byte nonce, AES-256-GCM and 16-byte tag. Never reuse key/nonce with different plaintext; retry the saved package unchanged.

SignedMessagePayload contains MessageBinding and EncryptedContent. AuthorKey account/chat must equal the operation account/binding chat. Author keys are scoped per account and chat. MembershipId/RightsVersion stay outside the immutable package so reauthorization never rewrites ciphertext.

AAD is UTF-8 compact JSON of this exact string array:
["chat-message-v1","1",accountContextId,deviceRegistrationId,localInstanceId,clientOperationId,chatId,authorKeyId,authorKeyVersion,"SendText"].
The restricted ASCII tokens make this deterministic without general JSON canonicalization.

SignedPackage is compact JWS: base64url(protected header) + '.' + base64url(payload UTF-8) + '.' + base64url(signature). Header has exactly alg=ES256, typ=chat-message+jws, kid=AuthorKeyId. Disallow unprotected headers, detached payloads, b64=false and crit extensions. Reject duplicate or unknown header/signed-payload fields, noncanonical base64url, wrong algorithm/version/key, invalid lengths and binding mismatches. ES256 signs the ASCII first two encoded segments using P-256/SHA-256 and exactly 64-byte big-endian R || S (IEEE P1363), not DER. Public keys use DER SubjectPublicKeyInfo; encrypted private recovery exports use PKCS#8.

Preserve original signed bytes; verification must not deserialize/reserialize first. PackageDigest is base64url SHA-256 of the entire compact JWS ASCII bytes. Re-signing or reordered JSON changes the package identity. SendMessageRequest.MessageKey and MessageKeyGrant.MessageKey are transient 32-byte keys over authenticated TLS only; never persist them directly in SQLite/outbox/broker/logs. Key grant MessageId must match envelope MessageId. Every MessageDelivery also carries AuthorVerificationKey with the complete AuthorKeyReference and canonical base64url DER SubjectPublicKeyInfo for P-256. The reference must exactly equal the signed binding (including account, chat, key ID and version), and the account/chat must match the envelope. The key comes from the server-authorized author-key registry over authenticated TLS, never from an untrusted JWS header or embedded client-supplied key. Once a reference is bound to SPKI, a different SPKI for that same reference is a conflict; rotation uses a new version. Recipients import this key and verify the saved signed bytes before Received/DataReady. Live delivery materializes keys only after final recipient authorization. Protected persistence belongs to the later key-module plan.

## Results, order and receipts

New acceptance serializes rights checks with membership/blocking changes and atomically commits message, protected key, operation result, logical changes and outbox. Allocate stream positions under transactional locking through commit. MessageSequence orders messages; ChangeSequence orders all chat changes. Catalog uses independent per-account sequence. Compare versions only inside their own entity/stream. CreatedAtUtc and MessageId are the priority tie-breaker.

OperationResult is discriminated by outcome:

- Accepted contains immutable original IDs/time/digest and OwnSendThroughSequence. After authenticating active session/device, consult the own operation result before checking current membership. Return the original result across retries and membership changes.
- Unknown means no committed result at lookup's serialization point; an in-flight attempt may still commit. Retry only the same operation/package and reconcile before discarding or advancing the per-chat queue.
- Retryable means this attempt did not accept and supplies nonnegative retryAfterMs. Use Unavailable, RateLimited or SessionExpired. Concurrent ambiguity still requires reconciliation.
- Rejected definitively rejects the attempted package and stops automatic retries. OperationConflict must not delete or replace a previously accepted result. Query the original operation before discarding an ambiguous local attempt.

The serializer emits the outcome discriminator first. These results flow server-to-client; when replaying the same JSON through the .NET 8 polymorphic deserializer, preserve that property order (it does not support a trailing discriminator). JavaScript consumers compare property values, not order. The probe checks all four real JSON variants against TypeScript-checked fixtures.

Timeout/disconnect means Unknown, never Rejected. Per device/chat, B waits for A's Accepted or explicit removal of a definitively unaccepted A. Other chats can proceed independently.

CiphertextStored is private device progress. Received requires transaction completion, available key and successful signature/decryption. Only Seen carries Observation; other receipt kinds require null. Seen requires normal mode, active uncovered focused chat and continuous 50% visibility for 500ms (50% of viewport for oversized messages). Server derives the device/account from authenticated session and checks supplied context.

Recipient state is per person, excluding sender from group proportions; device state is per registration/local instance. First durable recipient Seen fixes its reason/time: Observed, HistoryShared or OwnSend. Later device observations never replace it. Frozen archive receipts only update private device progress. NotApplicable is terminal for stale public receipts; Applied/AlreadyApplied have StateVersion, NotApplicable has null. Supply membership scope for late offline receipts.

Offline Seen preserves original client time. Reliable server-authenticated sample records before disconnect and after reconnect must both be within 60000ms inclusive. Missing/unreliable/out-of-range samples or observation before message creation/after server receipt use server receipt time. Echoed client timestamps alone cannot prove reliability. Age alone does not invalidate offline Seen.

## Sync, cursors and events

Handshake authenticates SessionContext and installs connection addressing before fixing boundaries. Full mode persists until the account/local-instance initial restore marker completes, including after restart. Fix catalog/priority set (up to ten chats), all boundaries, RightsVersion and snapshots durably before returning SyncHandshakeResponse. The initial request contains only ProtocolVersion and SessionContext, never the full position list. The response contains the catalog boundary, bounded priority IDs and BoundaryCursor (null only when there are no chat boundaries).

Fetch the fixed chat/member boundary set with SyncBoundaryPageRequest/SyncBoundaryPage. Cursor is the initial BoundaryCursor or the previous NextCursor; it binds the same session, rights and immutable snapshot. Limit is 1..25 and actual responses must fit 32768 bytes including SignalR framing. NextCursor is null exactly when Complete=true. Retries of a cursor return the same page; subsequent pages use its continuation. Even a full restoration can enumerate arbitrarily many chats this way. A later rights change invalidates this enumeration rather than mixing snapshots.

Upload local positions with SyncPositionBatch, Kind=Resume. The same bounded exchange serves Acknowledge and periodic Check; these operations share only transport batching, not their business meaning. Each exchange has a new ExchangeId, starts at BatchIndex=0, increments by one and ends with Final=true. Each batch has at most 25 distinct positions and must fit the wire byte cap. An empty final batch represents an empty set. Wait for SyncPositionBatchResult echoing the exchange/kind/index before sending the next batch. Identical retries return the saved result; a changed batch with the same exchange/index, a gap, a repeated stream, or a batch after Final fails InvalidRequest. Exchange identity is bound to sync session, connection, rights and kind, and remains valid only for that sync session. Complete=true acknowledges an accepted Final after all earlier indices; it does not itself mean LiveReady.

Resume must include every persisted local stream position (omitted newly authorized streams start at zero). The server records the completed resume set before declaring readiness; partial uploads cannot complete initial restoration. For Acknowledge it verifies continuity up to each submitted fixed boundary. Check compares the submitted positions with authoritative positions and triggers catch-up on differences. ServerPositions in each result covers exactly the submitted streams, in order; DataReadyScopes is a subset of the submitted chat scopes whose data boundary has been acknowledged. Both result arrays are bounded by the current batch, never the entire account. Per-scope readiness is accumulated by the client for this connection/rights version. SyncReadiness carries only global flags; it cannot turn true until all required scope acknowledgements and the resume exchange are complete. Reconnect or RightsChanged invalidates the exchange and all readiness confirmations.

Catalog StreamPosition requires null ChatId/MembershipId; Chat requires both. Boundary Scope is null only for Catalog. Membership snapshots carry disjoint permitted ranges, snapshot IDs and optional frozen change boundaries. Rejoin unions old frozen archive with newly shared/current ranges without filling inaccessible gaps. Resolve archive metadata/status at the named snapshot, not today's state.

Cursors are opaque random 256-bit tokens referencing durable PostgreSQL state shared by replicas, max 2048 bytes. Bind them to account, registration, local instance, sync session, stream, membership, rights version, snapshot, direction, fixed upper bound and next position. They are not authority. Revalidate session/current rights on every page. Invalid/expired/mismatched cursor returns CursorInvalid and starts allowed-state reconciliation preserving pending send/Seen queues. RightsChanged requires new handshake/readiness. Cursor lifetime follows sync session; expiration preserves applied positions.

SyncPage and LiveEvent share SyncChange. Exactly one nullable payload is populated and matches Kind; remaining payloads are null. Chat changes require Scope. MembershipEvent is a durable, history-recoverable system event with Added, Left or Removed, subject and UTC time; it distinguishes a voluntary departure from removal even on a newly restored device. ActorAccountContextId is null whenever unauthorized, and always null for a Removed event delivered to the removed subject. Permission filtering retains the subject's own exit event. This is distinct from the current Active/Frozen membership snapshot; permitted system events remain recoverable in history. EventId deduplicates delivery; entity Version prevents stale pages replacing newer live state; Position orders changes. Persist parent chats before messages in the same transaction. Retain status arriving before its body for later association.

Pages are bounded by both 100 items and 1048576 serialized UTF-8 bytes, including keys/envelopes. Pages may be smaller but must advance or terminate. Complete=true iff NextCursor=null and AppliedThrough reaches the fixed stream boundary. Empty terminal pages are valid. Live events never advance the HTTP cursor. No page/event implies Received before local commit and cryptographic checks.

Acknowledge position exchanges bind current connection/session/RightsVersion. Verify continuous positions and current rights before LiveReady. DataReady requires allowed data through fixed boundaries with no temporarily pending key/decrypt work. Isolated permanently invalid records may be quarantined with durable diagnostics and no Received. Full restoration opens only after all required chats; subsequent sync after the fixed priority set. Reconnection invalidates LiveReady and repeats handshake.

Future hub methods: Handshake, GetBoundaryPage, SendMessage, QueryOperation, Receipt, ExchangePositions (Kind=Resume/Acknowledge/Check). Events: Change (LiveEvent), SessionControl. HTTP history/catalog/delta take SyncPageRequest and return SyncPage or non-success SyncFailure. Authorization failures are not successful empty pages.

## Transport limits

MaxHubMessageBytes=32768 includes complete SignalR framing. MaxSignedPackageBytes=24576 leaves envelope room; text is base64-expanded twice inside JWS. Enforce actual complete wire sizes at send/receive; do not silently raise legacy limits. Probes check worst-length SendMessage invocation and complete position/boundary exchanges containing 301 maximum-length stream identifiers. Receipt batches cap at both 50 and 32768 bytes. Position batches cap at 25 and boundary pages at 25, in addition to the byte cap. Handshake is constant-sized apart from the at-most-ten priority IDs. Large catalog metadata must use bounded HTTP pages; an individual metadata entity still exceeding the HTTP page cap fails explicitly rather than producing an unbounded response. HTTP pages cap at 1MiB. Oversize requests fail PayloadTooLarge before acceptance. Never split one signed package across invocations.

## Sessions, enrollment and key protection

Access tokens bind account/session/device and require current trust on every operation. Expiry triggers device refresh; revocation terminates affected connections. Refresh tokens are opaque random secrets, hashed at rest, rotated transactionally. Persist RefreshOperationId before submission. Identical retries return the same rotation result within a bounded replay window; reuse under a different operation ID revokes the family. Unknown network outcome retries the same operation. RefreshSessionResult has Tokens only for Rotated and RetryAfterMs only for Retryable; other outcomes require both null. Reauthentication preserves protected local data.

Challenges have one-use 256-bit nonces, five-minute expiry and server-side purpose/account/registration/public-key binding. Device proof is ES256 over UTF-8 compact JSON array ["chat-device-proof-v1",challengeId,purpose,accountContextId,deviceRegistrationId,keyId,spki,nonce,expiresAtUtc]. Approval uses the same array with domain "chat-device-approval-v1" and approving device key. Validate trust at commit; supplied ApprovingSession is not authority. Refresh uses SessionBinding challenges additionally bound server-side to SessionId/RefreshOperationId.

After explicit revocation, unknown/revoked registrations require another currently trusted device even with valid recovery. Without it old context stays blocked. RecoveryKdf algorithm is argon2id v0x13 with 32-byte output, 16-byte random salt; candidate parameters memory=65536KiB, iterations=3, parallelism=1 require phone measurement. Bound resource parameters before derivation. Recovery AAD is UTF-8 compact JSON of the exact all-string array:
["chat-recovery-v1","1",accountContextId,recoveryVersion,"argon2id","19",salt,memoryKiB,iterations,parallelism].
Here "19" denotes Argon2 version 0x13 in decimal; salt is canonical unpadded base64url of the 16-byte salt; resource integers are canonical unsigned decimal strings, without leading zeroes. The account/version rules above apply. There are no spaces, BOM, trailing newline or extra fields. The KDF metadata is authenticated as well as validated before derivation. The shared Node/.NET recovery fixture proves these AAD bytes and AES-GCM binding, using a fixed derived key; native Argon2 derivation remains an explicit integration check. System password-manager recovery entry (phone username) is separate from app Keychain/Keystore secrets and survives logout.

Server protected-key records use AES-256-GCM with 32-byte master key, fresh 12-byte nonce and 16-byte tag. Store format/master-key versions, owner context, purpose, key ID, nonce/ciphertext/tag; This is an internal key-module storage format, not a client wire format. Its exact AAD encoding and migration version must be specified and tested in the key-module plan before storage is activated; it binds all nonciphertext identifiers. Master secret is mounted read-only outside PostgreSQL behind a replaceable provider in the later key module. Retain old master versions through rewrap. Rotation never changes message ciphertext, author package, MessageId or rights version. A DB dump alone must not unlock keys; diagnostics exclude plaintext keys and tokens.
