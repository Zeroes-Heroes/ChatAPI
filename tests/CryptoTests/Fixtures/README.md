# Cross-language fixture

`cross-language-fixture.json` is generated by `ChatAppClient/__tests__/crypto/fixtures.generate.test.ts`
from the real client-side production crypto module (`MessagePackage.build`/`Jws.build`, backed by
`NodeCryptoHost` - which implements the same `CryptoHost` interface as the production `QuickCryptoHost`,
see that file's doc comment for why that substitution is legitimate here and not elsewhere). It is not
a hand-written or hardcoded vector.

To regenerate: run `npx jest __tests__/crypto/fixtures.generate.test.ts` in `ChatAppClient`, then copy
`ChatAppClient/__tests__/crypto/fixtures/cross-language-fixture.json` to this directory. The two repos
are separate git worktrees, so this copy step is manual, not part of either build.

`CrossLanguageFixtureTests.cs` loads this file and verifies the real package with the real
`MessagePackageVerifier`, and confirms each `tampered.*` variant is rejected.

The same file also carries a `recovery` section (stage 06): a real envelope sealed by the production
`RecoveryEnvelope.ts` under a FIXED derived key, with the pinned `chat-recovery-v1` AAD.
`CrossLanguageRecoveryFixtureTests.cs` rebuilds that AAD with `Services/Recovery/RecoveryAad.cs` and
opens the envelope with .NET's own AesGcm. Native Argon2id derivation is deliberately NOT part of this
fixture - it stays an on-device integration check (docs/sync-contract-v1.md).
